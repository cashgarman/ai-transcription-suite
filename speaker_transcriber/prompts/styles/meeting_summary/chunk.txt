Write detailed notes for this transcript segment. These notes are kept as the detailed record
of the meeting, so completeness matters more than brevity. Nothing you leave out can be
recovered later.

Cover only what is new in this segment. Any background supplied from earlier segments is there
so you can tell what is new. Never restate it, summarize it, or recap it.

## Structure

- Use `##` headings named for the actual topics discussed, in the order they came up. Never
  use a generic heading such as Discussion, Notes, Meeting Notes, Summary, Overview, Recap,
  Segment, or Continuation.
- Under each topic write compact Markdown bullets, not flowing prose. One bullet per point,
  attributed inline to the speaker by the name or label the transcript uses. The shape:

## Packaged Build Failures

- Cash: the packaged build fails on the shader step; the editor build is fine.
- Andrew: suspects the June driver update and will test on the older driver today.

- Do not write a participants list; the names belong on the bullets.
- After the topics, add these headings only when this segment has material for them:
  `## Decisions`, `## Action items` (owner, action, and priority when stated), `## Questions`
  (asked, and answered when they were answered), `## Risks and blockers`, and
  `## Technical details` (numbers, versions, file names, deadlines, constraints, systems).
- Omit any heading you have nothing to put under. Never write a filler line such as "None",
  "None raised in this segment", or "No decisions were recorded".

## Content

Preserve every substantive topic, decision, request, concern, question, answer, number,
deadline, name, role, action item, constraint, risk, dependency, blocker, and technical detail
from this segment. Include the reasoning people gave, the examples they used, the
disagreements, and the answers to questions. Drop only filler and verbatim repetition. Do not
compress a long exchange into a single sentence.

## Output

Start directly with the first `##` topic heading. Do not write a document title, a preamble, a
lead-in sentence, or a closing summary. Do not echo the `[MORE SEGMENTS FOLLOW]` or
`[END OF TRANSCRIPT]` marker. If more segments follow, do not write a closing assessment and
do not claim the meeting ended.
